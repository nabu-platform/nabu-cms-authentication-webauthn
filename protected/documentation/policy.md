# WebAuthn policy (source)

`utils.getPolicy` resolves policy using a trusted, server-injected `webApplicationId`; `nabu.web.application.Services.information` supplies the HTTPS host, aliases and port. The browser's origin is checked against exact configured HTTPS origins, never used as configuration. The persisted check requires `secure=true`, scheme `https`, a host and a port in 1..65535 when specified. The scoped `nabu.web.application.Services.configuration` lookup uses that application ID, the `configuration.policy` type and path `/`; no policy document is required. A path-specific policy not matching `/` is not selected. The underlying resolver does not report ambiguous equal-specificity configurations; do not configure competing matching documents until ambiguity detection is implemented. Ambiguity rejection remains incomplete.

Per-field precedence is an explicitly populated application `configuration.policy` field, then a system property, then app-derived/default value. System property names (read via `nabu.utils.Server.property`) are `nabu.cms.authentication.webauthn.rpId`, `nabu.cms.authentication.webauthn.origins` (comma-separated exact HTTPS origins), `nabu.cms.authentication.webauthn.timeoutSeconds` (1..300), and `nabu.cms.authentication.webauthn.requireUserVerification` (`true` or `false`). The default timeout is 120 seconds and UV defaults to true. A local boolean false remains explicit and overrides system true. RP defaults to the application host; origins default to HTTPS host and aliases with the configured HTTPS port (443 omitted). The primary origin is assigned at index zero and aliases are appended using `nabu.utils.List.add`. The resulting RP must be the origin hostname or its DNS suffix. Unrelated sibling aliases need an RP shared by all included hosts, or explicit origins limited to compatible hosts; otherwise resolution fails closed. Authentication and registration browser `timeout` fields map the effective `timeoutSeconds * 1000` in milliseconds; their REST output contracts include the field. Live tests of policy derivation on an HTTPS application and false precedence were not possible in the available HTTP-only application.

Do not expose policy as an arbitrary input to registration, assertion or typed authentication. Service calls that lack a trusted application ID fail closed. Do not deploy until ambiguous applicable policy documents are rejected and policy derivation is tested with an HTTPS application; the underlying configuration resolver currently does not expose competing matches. Verify application HTTPS metadata, scoped configuration, certificate and live infrastructure before enabling. No schema synchronization or production data writes were performed in this policy change.
